---
title: "Known limitations and deliberate simplifications"
---

-   **Name-based relations, not type-resolved.** `find_calls`/`find_callers`/`find_references` match on plain text. Two unrelated functions named `parse` in different files/languages are indistinguishable by name alone — a query for "callers of `parse`" returns _every_ caller of _any_ `parse`, disambiguated only by reading `relative_path`/`language` in the result. Architecture, not a bug — real overload/import resolution per language is a much larger scope.
-   **`to_symbol_id` is best-effort and unused by queries.** Populated via `SELECT id FROM symbols WHERE name = ?1 LIMIT 1` (first match, arbitrary on ambiguity) but no shipped query joins on it.
-   **Test detection is a naming heuristic, not framework-aware.** `impact_analysis`'s "likely affected tests" is `name.to_lowercase().starts_with("test")` — no recognition of `#[test]`, pytest fixtures, JUnit annotations, etc.
-   **CSS only indexes simple selectors.** `.foo`/`#foo` alone become `Rule` symbols; compound selectors (`div.foo`) and combinators (`.a .b`, `#id > .c`) are skipped — matching which elements they actually reach needs a DOM, not an AST.
-   **Plain XML never emits relations.** `mct-lang-xml` indexes `id`/`name`/`Name`\-attributed elements (case-exact, in that priority) as `Element` symbols for structure only — there's no dialect-generic convention to cross-reference (a Maven POM and an Android layout mean completely different things by their attributes).
-   **Markdown relation targets are references, not resolved links.** Each file produces a `Module` symbol for the note and `Element` symbols for ATX and setext headings. Wikilinks, embeds, tags and frontmatter title/alias/tag values produce relations; the index does not validate that each target exists. Paragraph and table-row text is searchable with quoted `hybrid_search` queries, but is not indexed as symbols. Code spans are excluded from relation scanning, and code blocks/frontmatter are excluded from prose-literal search.
-   **XAML's event-handler cross-referencing is a bounded allowlist, not a heuristic.** `EVENT_ATTRIBUTE_NAMES` in `mct-lang-xaml` lists ~40 common WPF/UWP/WinUI/MAUI/Avalonia event names (`Click`, `Loaded`, `SelectionChanged`, ...) — an attribute outside that list, even if it wires up a real code-behind handler, won't produce a `References` relation.
-   **`mct-lang-powershell` doesn't index classes.** `class Foo { ... }` and its methods are invisible to the index — only `function`\-style definitions are, since the scope this plugin was built for is systems-scripting `.ps1`/`.psm1` files, where classes are rare.
-   **`mct-lang-bash`/`mct-lang-powershell` only index top-level variables**, and every command/cmdlet invocation is recorded as an unresolved `Calls` relation regardless of whether it turns out to be a local function or an external program — same "resolved downstream, matched by name" precedent as every other language here.
-   **`mct-lang-php` reuses `SymbolKind::Trait` for PHP's `trait` keyword**, the same tag `mct-lang-rust` uses for Rust traits — the two are semantically different (a PHP trait is a code-inclusion mixin, not an interface-like contract), sharing only the tag name, not the meaning.
-   **`mct-lang-php` records `use TraitName;` (trait composition) as a `RelationKind::Implements` relation** on the enclosing class/enum — the closest existing relation kind, though not a perfect fit. `mct-core` has no dedicated "uses/composes" relation kind today.
-   **`KNOWN_PENDING_LANGUAGES` is a short, hardcoded list** (swift, ruby) — any other genuinely unsupported language's files are skipped with zero visibility in `status`.
-   **Exclude patterns aren't user-configurable** from either binary today ([File exclusion rules](/docs/exclusion)), despite the underlying API supporting it.
-   **Background watching is scoped to a running MCP server.** The server reindexes after file changes settle; set `--reindex-debounce-ms 0` to disable the watcher. The CLI does not run a persistent watcher, and changes made while the server is stopped are picked up when it starts again.
-   **Binary files sharing a supported extension are silently skipped**, not reported as a parse failure — they fail the UTF-8 check before parsing is attempted.
-   **One index per `--root`, single-process, single in-flight operation.** The MCP server serializes all tool calls behind one `tokio::Mutex<Index>` — fine for interactive use, not built for high-concurrency multi-client access.
